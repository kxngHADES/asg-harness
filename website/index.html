loop

loop

Treats your message as an objective. The harness splits it into steps, checks each one and runs your tests.

/loop add rate limiting to the API
step 2/5 · review passed
verify · go test ./... ok

/loop <objective>

The harness decides what happens next. Not the model.

Small local models do their best work with a short, fresh context. So each step gets one, every step is reviewed, and nothing is called done until your tests pass.

  1. PlanBreak the objective into steps
  2. WorkOne step, fresh context
  3. ReviewPass, retry or split
  4. VerifyRun your tests
  5. Review ×4Four angles, then done

Runs save after every step. /loop resume picks up after a restart, a question or Ctrl + C.

Just the terminal app

One line.
Then type asg.

The script picks your OS and CPU, checks the SHA-256 checksum and puts asg on your path. asg update upgrades in place.

For local models, install Ollama and pull one: ollama pull qwen3.5:9b. For hosted models an API key is enough.

any OS with Go

go install github.com/kxngHADES/asg-harness/cmd/asg@latest
